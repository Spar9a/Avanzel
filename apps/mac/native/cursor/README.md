# avanzel-cursor

The part of "dictate into any app" that only the Mac itself can do: it watches one modifier key (a tap of Right Option
starts and ends a dictation), says which app the keys go to and whether its cursor takes text, and pastes text through the
clipboard, giving the person's clipboard back after.

It is a long-running helper. Commands come in on stdin and events and replies go out on stdout, one JSON object per line;
diagnostics go to stderr. It exits when stdin ends or on SIGTERM or SIGINT.

Out (stdout):

- `{"event":"ready","accessibility":bool,"inputMonitoring":bool}` once, at start.
- `{"event":"modifier","key":"right-option","down":bool}` for each change of the watched key.
- `{"event":"key"}` for any other key-down or mouse-down, and for a change of any other modifier (shift, command, control,
  the other option, fn, caps lock): what breaks a tap, so a bare ⌥⇧ (switching layouts) or ⌥⌘ never starts a dictation.
  Sent only after a `watch`; it carries nothing about which key.
- `{"event":"error","message":"..."}`.
  Also used for a line that is not JSON or has neither `id` nor `cmd`.
- A reply carries the request's `id`: `{"id":1,"ok":true,...}` or `{"id":1,"ok":false,"message":"..."}`. Every success
  reply carries `"ok":true` beside its own fields. A line with an `id` but no usable `cmd` gets an `ok:false` reply.

In (stdin):

- `{"id":1,"cmd":"watch","key":"right-option"}`. Keys: `right-option` (code 61), `left-option` (58), `right-command` (54),
  `right-control` (62). Left and right are told apart by the key's own device flag bit. Replies `ok:false` while the
  keyboard cannot be watched yet (no Input Monitoring); the key stays chosen, and a later `watch` or `permissions` makes
  the tap once the permission is there (a tap made without it is dropped, so no restart is needed).
- `{"id":2,"cmd":"permissions","prompt":bool}` replies `ok:true`, `accessibility` and `inputMonitoring` (`ready` computes
  `inputMonitoring` the same way). `prompt:true` asks macOS for both. Start-up itself never raises a dialog.
- `{"id":3,"cmd":"inspect","keep":bool}` replies `ok:true`, `app` (`name`, `bundleId`, `pid`; name and bundleId can be
  null), `window` (`title`, or `null` when there is no focused window or it cannot be read) and `element` (`role`, `secure`,
  `takesText`; `null` when Accessibility is not granted or nothing could be read). `role` can be null.
  The app is the one the keys go to: Accessibility's focused application, which also finds non-activating panels
  (Spotlight, Raycast, 1Password Quick Access) that are never "frontmost"; the frontmost app when that can't be read.
  `takesText` is `"yes"` for text fields, text areas, combo boxes, search fields, secure fields and editable elements; `"no"`
  when the focused element is positively not text (button, list, outline, table, image, and the like) or when the app has
  no focused window (then `element` is present with `role` null if it had none); otherwise `"unknown"`. Every Accessibility
  question has a 0.5 s limit, and a failed one gives nulls and `"unknown"`, never an error.
  `secure` is true for a password field, and also whenever macOS's secure keyboard entry is on (a password field anywhere, a
  terminal's Secure Keyboard Entry): then `element` is never null (`{"role":null,"secure":true,"takesText":"unknown"}` when
  nothing else could be read), so what is said then is kept nowhere. Taps still work in that state.
  `keep:true` (optional) remembers the focused window's Accessibility element and the app, for `same`.
- `{"id":4,"cmd":"same"}` replies `ok:true` and `same`: `true` when the focused window now is the very window the last
  `inspect` with `keep:true` found (the same Accessibility element, `CFEqual`, in the same app), `false` when it is another
  window or another app, `null` when nothing was kept or the focused window can't be read now. Two windows with the same
  title are told apart, and a title that changes by itself (an unread count, a terminal's title) doesn't count as a move.
- `{"id":5,"cmd":"paste","text":"...","holdMs":400}` pastes `text` into the focused app, the clipboard borrowed and given
  back:
  1. every item on the general pasteboard is kept, with all its types and their data (copied files, spreadsheet cells, TIFF
     images and anything else, not only text);
  2. the pasteboard is cleared and `text` is written as plain text with the markers `org.nspasteboard.TransientType`,
     `org.nspasteboard.ConcealedType` and `org.nspasteboard.AutoGeneratedType`, so clipboard managers (Maccy, Raycast,
     Alfred, Paste) don't keep it; its `changeCount` is noted;
  3. Command-V is posted with the key that types "v" in the current keyboard layout with Command held (Dvorak moves it;
     "Dvorak - QWERTY ⌘" and Cyrillic layouts keep it at code 9), falling back to the ASCII-capable layout, then code 9;
  4. after `holdMs` (default 400, at most 5000), spent off the main thread so the key tap keeps running, the kept items are
     put back, but only if the `changeCount` is still the one it wrote: if something else was copied meanwhile, that stays;
  5. replies `{"ok":true,"restored":bool}`.
  On a failure (the text couldn't be written, the keystroke couldn't be made) the kept items are put back first, then it
  replies `ok:false` with a plain message. Without `text` it only posts Command-V (the same key code), as before.
  Replies `ok:false` with a plain message without Accessibility, before touching the pasteboard.

Needs the Input Monitoring permission (to see the key) and Accessibility (to inspect and to paste). Without Input
Monitoring it still starts, says `inputMonitoring:false` in `ready`, and answers every command.

The app (`src/main/cursor-helper.ts`) starts the helper again when it exits by itself (after 1 s, 2 s, then 5 s; at most
three times in a minute) and tells it the key again.

Build: `node apps/mac/scripts/build-cursor.mjs` makes a universal binary (macOS 14.2) at `build/avanzel-cursor`
(git-ignored). `npm run dist` runs it, bundles the result into `Avanzel.app/Contents/Resources/cursor/` and signs it with the app.
